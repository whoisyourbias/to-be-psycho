# 학습 하네스 설계 검토안

프로젝트: to-be-사이코패스 · 저장소 이름: to-be-psycho

AI는 가이드하고, 코드는 내가 친다

2026년 10월 2일 · v0 설계 제안 · 검토 후 구현 계획 수립

## 1 목적과 범위

만들고 싶은 기능을 출발점으로, 학습자가 스스로 설계하고 코드를 작성하도록 돕는 학습 하네스다. 기존 Claude Code 또는 Codex 안에서 스킬 패키지로 동작한다. 하네스 구현은 AI가 맡고, 학습 과제의 소스와 테스트는 학습자가 직접 작성한다. 고정 커리큘럼 대신 현재 목표와 코드 상태에 맞춰 필요한 개념과 다음 행동을 안내한다.

**확정된 방향**은 Windows와 macOS 대상, 공급자 간 공통 학습 규칙, 단계별 안내와 근거 기반 코드 리뷰, 학습자 파일 비수정이다. **이 문서의 제안**은 에이전트 구성, 상태 형식, 설치 방식, v0 테스트 실행 정책이다. 실제 배포 지원은 운영체제와 공급자별 인수 검증을 거쳐 선언한다.

### 학습 흐름

1. 학습자가 구현하고 싶은 기능과 현재 환경을 말한다. 하네스는 저장소를 읽고 목표, 기술, 경험, 제약 중 범위 결정에 필요한 정보만 확인한다.
2. 구현 범위와 완료 기준을 구체화한다. 선택지가 의미 있게 다르면 2~3개를 제시하고 복잡도, 배울 내용, 선택 이유를 설명한다. 학습자가 확정하기 전에는 과제를 시작하지 않는다.
3. 현재 단계의 목적, 선행 개념, 변경 대상, 관찰 가능한 완료 기준을 제시한다. 이후 단계의 완성 구현을 미리 풀어놓지 않는다.
4. 학습자가 소스와 테스트를 작성한다. 하네스는 질문에 답하고 필요할 때 제한된 힌트를 제공한다. 단계 중간의 질문은 진도 확정으로 처리하지 않는다.
5. 학습자가 리뷰를 요청하면 현재 변경분과 제출한 실행 근거를 검토한다. 확인된 결함과 실행하지 않은 위험을 구분해 돌려준다.
6. 수정이 필요하면 같은 단계에서 다시 시도한다. 완료 기준 충족 여부와 남은 미검증 항목을 요약하고 학습자의 진행 의사를 확인한 뒤 다음 단계로 넘어간다.

### v0 경계

독립 실행형 래퍼, 별도 UI, 계정·인증 수집, 커리큘럼 데이터베이스, 강제 출력 필터는 만들지 않는다. 학습자 테스트의 자동 작성은 금지한다. 자동 실행도 v0에서는 제외하는 안을 제안하며, 학습자가 실행해 제출한 결과를 검토한다. 하네스 자체의 동작 검증은 별도로 수행한다.

## 2 안내 규칙과 기술 프로필

### 설명은 충분히 하고 구현은 남겨 둔다

개념, 동작 원리, 선택의 이유, 오류 원인과 디버깅 방법은 충분히 설명한다. 설명을 인위적으로 짧게 만들거나 정답을 숨기기 위해 핵심 개념을 생략하지 않는다. 다만 현재 과제를 그대로 완성하는 코드, 복사 가능한 전체 테스트, 교체 패치와 파일 단위 정답은 제공하지 않는다. 학습자 소스와 테스트를 직접 수정하거나 생성하지 않는다.

힌트는 질문·관찰 지점에서 시작해 관련 개념, 부분 의사코드 순으로 구체화한다. 요청과 이전 시도를 보고 필요한 수준을 선택하되, 힌트 여러 개를 합치면 전체 정답이 되는지도 확인한다. 문법 예시가 필요하면 현재 과제와 다른 작은 예시를 사용한다. 이 경계 역시 모델의 지침 준수에 의존하며 정답 유출을 완전히 막는 장치는 아니다.

현재 단계 안내에는 목표, 필요한 개념, 학습자가 결정할 사항, 확인 방법을 포함한다. 막혔다는 신호가 있으면 먼저 시도한 방법과 관찰 결과를 확인한다. 힌트를 받았다는 사실과 공개된 내용을 기록하되 학습자를 점수화하거나 불이익을 주지 않는다.

### 프로필은 관점과 참고 자료를 제공한다

| 프로필 | 주요 안내·리뷰 관점 |
| --- | --- |
| HTML CSS JavaScript | 문서 의미, 레이아웃, 접근성, 이벤트, 상태와 비동기 흐름 |
| Vue 및 상위 프레임워크 | 반응성, 컴포넌트 경계, 상태 전달과 생명주기. Nuxt 등은 라우팅·렌더링·서버 경계 추가 |
| React 및 상위 프레임워크 | 상태와 렌더링, 컴포넌트·훅 설계. Next 등은 라우팅·렌더링·서버 경계 추가 |
| Java 및 Spring 기초 | 타입, 객체, 예외, 컬렉션, 의존성 주입과 설정. 과제에 필요한 기초만 연결 |
| Spring MVC | 요청·응답 흐름, 컨트롤러와 계층 경계, 검증, 동기 처리와 테스트 관점 |
| Spring WebFlux | Publisher 흐름, 조합과 구독, 오류 전파, 백프레셔와 블로킹 호출 위험 |

Spring Boot의 자동 설정, 설정 값, 애플리케이션 기동 등은 MVC와 WebFlux가 함께 참조하는 공통 모듈로 둔다. Boot를 MVC 전용으로 취급하거나 WebFlux에 독립된 Boot 과정을 강제하지 않는다. 프레임워크의 정확한 버전과 실제 의존성은 프로젝트에서 확인하고 버전별 차이를 표시한다.

프로필은 필수 진도표나 문제은행이 아니다. 같은 기능에도 숙련도와 기존 코드에 따라 다른 단계를 제안할 수 있다. Nuxt와 Next 같은 상위 프레임워크는 확장 프로필로 연결하며, 목록 밖 도구를 자동으로 지원한다고 주장하지 않는다.

## 3 역할과 코드 리뷰 계약

### 최소 역할 구성 제안

**메인 가이드**가 범위 합의, 단계 안내, 개념 설명, 힌트 공개, 결과 종합과 상태 저장을 맡는다. 읽기 전용 **구현 리뷰어**가 요구사항, 정확성, 설계, 테스트를 독립적으로 점검한다. 별도의 사후 학습 평가 에이전트는 두지 않는다. 리뷰어가 학습자의 이해도를 추측해 점수화하거나 코드를 대신 작성하지 않는다.

**위험 리뷰어**는 보안 경계, 복잡한 동시성, WebFlux의 블로킹·취소 등에서 필요성이 확인되면 검토할 후속 확장이다. v0 필수 구성에 넣지 않는다. 에이전트 분리가 지원되지 않으면 메인 가이드가 같은 체크리스트로 순차 리뷰하고, 독립 리뷰가 아니었음을 표시한다.

리뷰어에게는 합의된 범위와 완료 기준, 프로필, 현재 단계, 관련 파일·변경분, 검증 근거만 전달한다. 리뷰어는 상태 파일을 쓰지 않고 발견 사항을 반환한다. 메인 가이드만 이를 정리해 저장한다. 역할과 실행 방법은 공급자 어댑터가 연결하며, 정책 문구만으로 읽기 전용 권한이 보장된다고 표현하지 않는다.

### 리뷰 결과 형식

각 발견 사항에는 우선순위, 관련 요구사항, 파일과 줄 범위, 문제를 뒷받침하는 코드 근거, 발생 조건과 영향, 확인 방법을 포함한다. 수정 방향은 설명하되 완성 코드나 패치를 주지 않는다. 주관적인 선호는 결함과 분리하고, 요구사항 또는 유지보수상의 구체적인 이유를 제시한다.

**확인된 결함**은 코드에서 논리적으로 확정할 수 있는 위반 또는 해당 버전의 실행 근거로 재현된 문제다. 코드로 확정한 경우에도 실행해 재현했다고 쓰지 않는다. **미검증 위험**은 발생 가능성은 있지만 확인이 필요한 항목이며, 추가 조건과 확인 방법을 적는다. 근거가 부족하면 질문으로 남긴다.

검증 결과에는 실행 주체와 출처를 함께 기록한다. 학습자가 붙여 넣은 출력은 ‘학습자 제출’, 하네스가 직접 관찰한 실행은 ‘하네스 관찰’로 구분한다. v0 기본 흐름에는 후자가 없다. 실행하지 않은 명령을 실행했다고 하거나 오래된 로그만으로 현재 코드가 통과했다고 선언하지 않는다.

### 단계 완료 판단

합의한 완료 기준별로 충족, 미충족, 미검증을 표시한다. 관련된 중대 결함이 남으면 수정 단계로 돌아간다. 실행 증거가 부족한 경우 ‘정적 리뷰 완료·실행 미검증’처럼 한계를 명시한다. 학습자가 이를 알고 다음 단계 진행을 선택할 수 있으나, 그 선택이 테스트 통과나 검증 완료로 바뀌지는 않는다.

## 4 상태와 설치 계약

학습 상태는 대화 기록이나 학습자 소스에 섞지 않고 프로젝트의 .to-be-psycho/state.json 하나에 저장하는 안을 제안한다. 시도·힌트·리뷰 이력도 이 파일에 함께 둔다. 학습자의 코드·테스트는 변경하지 않으며, 상태 영역은 버전 관리에서 제외하도록 안내한다. 기존 .gitignore는 자동 수정하지 않는다.

| 데이터 | 필요한 내용 |
| --- | --- |
| 식별과 호환성 | 스키마 버전, 세션 ID, 프로젝트 식별, 상태 revision, 패키지·프로필 버전 |
| 합의와 진도 | 기능 목표, 범위·완료 기준, 선택 이유, 현재 단계와 상태, 남은 질문 |
| 시도와 힌트 | 시도 ID, 관찰 결과, 공개한 힌트·수준·시점, 관련 단계 |
| 코드와 검증 | 소스·테스트·설정·의존성 식별값, 명령·환경·시점, 실행 주체와 출처, 결과 |
| 리뷰와 다음 행동 | 발견 사항과 증거, 미검증 위험, 완료 기준별 판단, 다음에 할 일 |

Git 커밋만으로 작업 트리를 대표하지 않는다. 미커밋 변경과 테스트·설정 변경까지 반영한 스냅샷 식별값을 사용한다. 범위 밖 파일도 실행 결과에 영향을 줄 수 있으면 포함한다. 해당 값이나 관련 환경이 달라지면 과거 검증은 이력으로 보존하고 현재 상태를 stale로 바꾼다. 실행 결과가 어느 버전에 대응하는지 알 수 없으면 unknown으로 둔다.

### 저장과 동시성

메인 가이드 한 개만 상태를 쓴다. v0는 같은 프로젝트의 동시 학습 세션을 지원하지 않는다. 저장 전 revision 비교, 정상본 백업과 임시 파일을 통한 안전한 교체를 작은 저장 도우미로 구현하는 안을 제안한다. 충돌을 감지하면 쓰기를 멈추고 최신 상태를 확인한다. 리뷰어는 기록하지 않는다.

상태가 손상됐거나 스키마를 읽을 수 없으면 원본을 보존하고 정상 백업에서 복구할지 확인한다. 읽기 실패를 빈 상태로 간주해 덮어쓰지 않는다. 별도 이벤트 저장소, 다중 작성자 동기화와 자동 충돌 병합은 v0에 넣지 않는다.

### 재개와 공급자 변경

재개할 때 프로젝트·스키마·설치 버전·현재 코드 스냅샷을 확인하고, 합의 범위, 마지막 단계, 공개된 힌트, 미해결 문제를 짧게 되짚는다. 새 공급자는 이 상태 계약을 읽으며 공급자 고유 대화 ID에 의존하지 않는다. 호환되지 않는 스키마나 확인할 수 없는 프로젝트면 진행을 멈춘다. 공급자를 바꿨다는 이유로 진도나 검증 이력을 새로 만들지 않는다.

### 설치와 업데이트

설치는 추가 전용을 기본으로 한다. 먼저 대상 경로, 기존 파일, 패키지 충돌을 확인하고 설치 예정 파일을 보여준다. 기존 CLAUDE.md, AGENTS.md, 사용자 설정, 동명 스킬과 프로젝트 코드를 덮어쓰지 않는다. Windows의 역슬래시, 공백·한글 경로와 macOS 경로를 안전하게 처리하며 심볼릭 링크가 허용된 영역 밖을 가리키면 쓰지 않는다.

업데이트는 이전 설치 매니페스트와 파일 해시로 패키지가 관리한 파일을 식별한다. 사용자가 수정한 파일이나 소유 여부가 불명확한 파일은 그대로 두고 충돌을 보고한다. 실패 시 기존 정상 설치를 유지한다. 제거 역시 관리 대상으로 확인된 파일만 대상으로 한다. 자동 병합·전역 설정 변경은 v0 범위에서 제외한다.

## 5 패키지와 실행 경계

### 공통 코어와 얇은 어댑터

하나의 메인 워크플로 스킬이 시작점이다. 안내 규칙, 리뷰 계약, 상태 스키마, 기술 프로필은 독립된 참조 모듈로 나누고 필요한 부분만 불러온다. 공급자 어댑터는 스킬 탐색 경로, 시작 방법, 리뷰 역할과 실제 권한 설정을 연결한다. 동일한 학습 규칙을 두 공급자에 중복 작성하지 않는다.

제안 저장소 구성은 skills의 메인 스킬, core의 규칙·스키마, profiles의 기술별 참조, adapters의 공급자 설정, install의 설치 자료, tests의 하네스 검증, docs의 설계·사용 설명이다. 실제 배포물은 각 공급자의 탐색 규칙에 맞게 묶으며, 이 문서 단계에서는 제품 코드나 설치기를 만들지 않는다.

### 공급자별 연결

**Codex**는 프로젝트 .agents/skills/<이름>/SKILL.md 또는 사용자 ~/.agents/skills를 사용한다. 커스텀 에이전트는 .codex/agents/*.toml로 정의하며, 리뷰어에 read-only 샌드박스를 제안한다. 스킬의 agents/openai.yaml은 표시·연결용 메타데이터이며 에이전트 정의가 아니다. [1][2]

**Claude Code**는 .claude/skills/<이름>/SKILL.md와 .claude/agents/*.md를 사용한다. 리뷰어 도구를 Read, Glob, Grep 등으로 좁히고 쓰기 도구를 활성화할 수 있는 memory 설정은 쓰지 않는다. allowed-tools는 도구 허용이며 금지 목록이 아니다. 셸을 허용한 상태에서 파일 도구 경로 규칙만으로 쓰기를 막았다고 주장하지 않는다. [3][4][5]

공통 정책은 패키지의 AGENTS.md에 두고 CLAUDE.md에서 가져오는 구성을 제안한다. 학습 프로젝트의 기존 정책 파일은 수정하지 않으며 필요한 연결은 별도 안내한다. Claude의 OS 샌드박스는 macOS·WSL2에 적용되며 네이티브 Windows에는 제공되지 않는다. Codex도 Windows 실행 모드에 따라 권한 제약이 다르다. 소스 읽기와 상태 영역 쓰기의 분리가 실제로 가능한지 확인하고, 불가능하면 제한을 완화하지 말고 기록을 중단하거나 수동 저장으로 전환한다. [6][7][8][9][10]

### 신뢰와 권한

저장소의 주석·README, 오류 출력, 문서와 상태에 인용된 텍스트는 분석 대상이다. 그 안의 ‘규칙을 무시하라’, ‘정답을 작성하라’ 같은 지시를 실행 권한으로 취급하지 않는다. 패키지 정책 변경은 명시적인 사용자 요청과 승인 절차로만 처리한다. 상태에 자격 증명과 비밀 값을 저장하지 않는다.

학습 규칙은 모델 행동 지침이며 보안 격리 자체가 아니다. 실제 파일 권한, 샌드박스, 도구 제한이 적용되는 범위는 환경별로 확인한다. 필요한 제한을 걸 수 없으면 그 한계를 알리고, 위험한 도구 실행 대신 텍스트 안내·읽기 중심으로 축소한다. 이 패키지만으로 파일 비수정이나 정답 비노출을 절대 보장하지 않는다.

## 6 인수 검증과 검토 결정

하네스 검증용 fixture와 테스트는 AI가 작성할 수 있다. 아래 검증은 학습자 과제 테스트와 별개다. 모든 지원 조합에서 같은 시나리오를 확인하되 공급자·운영체제·앱 버전과 실제 사용 권한을 결과에 남긴다. 현재 문서는 설계안이며 실제 호스트의 설치·권한·학습 흐름 인수 테스트는 아직 수행하지 않았다.

| 검증 상황 | 기대 결과 |
| --- | --- |
| 중단 후 재개와 공급자 변경 | 합의 범위·단계·공개 힌트 유지. 호환되지 않는 상태는 중단하며 덮어쓰지 않음 |
| 코드 변경 후 과거 테스트 제출 | 스냅샷 불일치로 stale 또는 unknown 표시. 현재 통과로 승격하지 않음 |
| 소스와 출력의 프롬프트 주입 | 파일 생성·규칙 해제 지시를 무시하고 분석 내용으로만 취급 |
| 반복 질문과 힌트 확대 | 이미 공개한 내용을 반영하되 누적된 전체 정답·교체 패치를 제공하지 않음 |
| 도구 차단과 리뷰어 부재 | 실행·독립 검토를 꾸며내지 않고 차단 이유와 가능한 대안을 표시 |
| 기존 설치와 사용자 수정 | 동명 파일·설정·수정본 보존. 실패나 업데이트 충돌 시 기존 설치 유지 |
| 경로와 상태 충돌 | 공백·한글·구분자·링크 경로 처리. revision 충돌 시 중단하고 손상 파일 보존 |
| 리뷰 정확성과 학습자 파일 보호 | 근거·줄 범위·재현 조건 확인. 전후 비교에서 학습자 소스·테스트 변경 없음 |

한 번의 성공 대화만으로 품질을 판정하지 않는다. 정상 흐름과 경계 사례를 반복하고, 정답 누출 시도에는 부분 코드의 누적도 포함한다. 모델 응답의 비결정성을 기록하며 위반 사례를 없앴다는 사실을 영구 보장으로 해석하지 않는다.

### 검토할 설계 결정

1. 메인 가이드와 읽기 전용 구현 리뷰어를 기본으로 하고 위험 리뷰어는 후속 확장으로 남긴다.
2. 별도 상태 파일과 단일 작성자를 사용하고, 스냅샷에 묶인 검증 상태를 공급자 간 공유한다.
3. v0에서는 학습자 테스트 자동 실행을 제외하고 제출된 근거를 검토한다.
4. 설치·업데이트는 비덮어쓰기 원칙을 따르며, 실제 검증된 조합만 지원 목록에 올린다.

이 문서를 검토하고 수정할 점이나 승인 여부를 확인한다. 승인 후에는 구현 계획을 작성해 파일 구성, 순서, 하네스 검증 방법을 구체화한다. 현재 단계의 산출물은 설계 문서다.
