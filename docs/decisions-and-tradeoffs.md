# v0 결정과 트레이드오프

승인된 설계의 범위를 유지하면서 구현에 적용한 결정입니다. 사용에 영향을 주는 제약과 남은 검증을 함께 적었습니다.

1. **빈 저장소의 출발점**: 승인된 설계·계획을 로컬 기준 커밋으로 보존한 뒤 기능 브랜치에서 구현했습니다. 공개 저장소의 기존 이력을 임의로 만들거나 바꾸지 않았습니다. 게시 전에 원하는 브랜치 구조를 정할 수 있습니다
2. **배포용 프로젝트 패키지**: 결과물은 호스트별로 설치할 수 있는 프로젝트 소스와 배포물입니다. 사용자의 개인 스킬 저장소나 실제 학습 프로젝트에는 설치하지 않았습니다. 설치 대상 확인과 승인은 별도로 필요합니다
3. **검토 가능한 검증 기록**: 실제 테스트 출력, 코드 체크포인트와 행동 평가 원문을 근거로 남겼습니다. 자동화된 구현 진행표가 모든 계획 단계를 증명하는 형태는 아니므로, 더 깊은 감사가 필요하면 이 자료를 직접 대조해야 합니다
4. **수동 저장이 안전한 기본값**: 실제 호스트에서 소스 읽기와 상태 영역 쓰기를 분리할 수 있는지 확인되기 전에는 수동 상태 저장을 사용합니다. 읽기 전용 리뷰어 설정이 메인 가이드의 쓰기 권한까지 보장하지 않습니다. 편의성보다 파일 보호를 우선합니다
5. **기능별 체크포인트**: 커밋은 관련 구현과 검증 단위로 묶였으며 계획의 작업 번호와 엄격하게 일대일·시간순 대응하지 않습니다. 변경 이력을 볼 때는 기능과 검증 기록을 함께 따라가야 합니다
6. **보수적인 스냅샷 완전성**: coverage=complete라는 호출자 표시만 신뢰하지 않습니다. 루트의 .git과 .to-be-psycho를 제외한 일반 파일을 모두 목록에 포함하고 두 번 확인해야 합니다. 누락·링크·읽기 실패·변경 감지는 unknown입니다. 큰 생성물/의존성 트리는 complete 판정을 어렵게 만들 수 있지만 부분 근거를 현재 통과로 승격하지 않습니다
7. **원자성 보장의 범위**: Node 내장 기능으로 링크/별칭/하드링크를 거절하고 경로·바이트를 재확인합니다. 모든 OS에서 악의적인 극미세 경쟁이나 전원 손실을 완전히 막는다고 주장하지 않습니다. 더 강한 보장은 실제 호스트 샌드박스 검증 또는 수동 모드가 필요합니다
8. **관찰된 실패에 맞춘 안내**: 누적 정답 유출과 프레임워크 경계 누락에 실제 응답을 근거로 지침을 보완했습니다. 이미 통과한 사례에 추측성 규칙을 계속 덧붙이지 않았습니다. 새로운 표현·모델·과제에서도 같은 결과가 보장되는 것은 아닙니다
9. **설치 승인 계획의 동일성**: applyInstall은 현재 프로세스에서 발급된, 변경되지 않은 동일 plan 객체만 받습니다. 변경되거나 직렬화해 다시 만든 계획의 적용을 막습니다. 프로세스가 끝났다면 새 계획을 만들고 다시 검토해야 하며, 라이브러리 호출이 사용자 승인을 대신하지 않습니다
10. **복구 실패를 숨기지 않음**: rollback 중 목적지가 바뀌어 안전한 복원을 할 수 없으면 백업과 잠금을 보존하고 ROLLBACK_FAILED를 냅니다. 원래의 단순 결과 상태만으로는 이 상황을 진실하게 표현할 수 없습니다. 사용자가 자료를 비교해 수동 복구해야 합니다
11. **적용 완료와 정리 실패를 구분**: 파일 적용·해시 검증 후 정리만 실패하면 applied-with-cleanup-needed와 cleanup 경로/오류 정보를 반환합니다. 적용된 작업을 실패나 rollback으로 오해해 재시도하지 않도록 결과 상태를 확장했습니다. 호출자는 추가 상태를 처리하고 정확한 잔여 경로를 수동 확인해야 합니다

## 검증 범위

자동 테스트 139/139 통과, 현재 가이드·리뷰 행동 평가 45회에서 기록된 위반 없음. 기준선 40회와 수정 전 라우팅 평가 3회도 보존했습니다. 독립 코드 리뷰의 세 가지 중요 문제는 실패 재현 테스트를 추가한 뒤 한 번의 수정 묶음으로 처리했으며 미룬 발견 사항은 없습니다.

Windows native / macOS의 실제 Claude Code·Codex 설치, 권한 분리와 전체 학습 흐름은 모두 미검증입니다. Linux 단위 테스트나 텍스트 응답 평가로 이를 대신하지 않습니다. 자세한 근거는 [인수 기록](acceptance.md), [지원 표](support-matrix.json), [설치 안내](../install/README.md)를 참고하세요.
